Custom Self-Hosted Form Solution

Technical plan for replacing Tally.so with a fully owned, embeddable, self-hosted form platform.  Planning Phase

Project Overview

AJJ-Tally is a custom, self-hosted form solution replacing Tally.so. The core requirement is embeddability: a developer on any host website adds a single <script> tag and a <ajj-form> custom element, and a fully featured form renders inline, as a popup, or full-page — with no third-party SaaS dependency.

Embed Runtime

Vue 3 Web Component — single IIFE bundle. Shadow DOM isolates the form from the host page.

Backend API

Node.js + PostgreSQL — serves form schemas, persists submissions, sends email, dispatches webhooks.

20+ Field Types

Full feature parity with Tally.so: text, choices, date, rating, file upload, signature, and more.

Conditional Logic

All six action types with AND/OR condition groups. No limits on rule count.

3. Recommended Stack

Vue 3 (Composition API) + Vite + TypeScript + Tailwind CSS

Backend: Node.js (Express/Fastify) + PostgreSQL + Redis

Vue 3 achieves the highest weighted score and is the only candidate that satisfies all three critical constraints simultaneously:

  • defineCustomElement — packages the entire form as a native Web Component with Shadow DOM isolation. The host page's CSS cannot break the form; the form's CSS cannot pollute the host. Alpine.js and React do not have this as a first-class feature.
  • Composable architecture — useFormState, useValidation, useConditionalLogic, and useMultiStep are natural, independently testable Composition API composables. This structure is not achievable cleanly with Vanilla JS or Alpine.js.
  • Bundle size — Vue 3 runtime-only build ~22 KB gzipped. Full embed bundle estimatable under 60 KB gzipped. React's baseline alone is ~43 KB before any form field code.
  • Vite lib mode — outputs a single IIFE file (embed.iife.js) with tree-shaking. No module bundler required on the host site.

Composable Responsibilities

ComposableResponsibility
useFormStateReactive Map<fieldId, value> shared via provide/inject across all field components
useMultiStepPage array management: currentPageIndex, goNext(), goBack(), goToPage(n), progress percentage
useValidationEvaluates validationRules[] per field on blur, page advance, and submit; returns Map<fieldId, errorMessage>
useConditionalLogicEvaluates all IF/THEN rules; produces hiddenBlocks, requiredOverrides, jumpTarget, calculatedValues
useAnswerPipingReplaces @fieldName tokens in question text and Thank You page with current field values
useSubmissionHandles POST to /api/submissions; loading state, error handling, retry on network failure

Backend Submission Pipeline

  1. Validate Origin / Referer header against the form's authorised domains allowlist.
  2. Verify CSRF double-submit cookie token.
  3. Sanitise all string inputs (sanitize-html — strips script tags, HTML injection).
  4. Re-validate required fields and type constraints server-side (client-side validation is not trusted).
  5. Persist submission record to PostgreSQL.
  6. Store uploaded files to S3-compatible bucket; record object keys.
  7. Enqueue async email notification job.
  8. Enqueue async webhook dispatch job (5-attempt retry schedule).
  9. Respond 201 Created with { submissionId }.

5. Implementation Roadmap

Phase 1 — Foundation and Core Field Rendering

Goal: A working embeddable form that renders fields from a JSON schema and submits data.

  • Project scaffolding: Vite + Vue 3 + TypeScript + Tailwind; Docker Compose (API + PostgreSQL + Redis)
  • Web Component entry point using defineCustomElement
  • 10 core field components: Short Answer, Long Answer, Email, Phone, Number, Multiple Choice, Dropdown, Checkbox, Date, Time
  • useFormState, useValidation, and useMultiStep composables with progress indicator
  • Backend: GET /api/forms/:id, POST /api/submissions, PostgreSQL schema, basic SMTP self-email
  • Origin validation, input sanitisation, HTTPS enforcement, CORS
  • scripts/start.sh and scripts/stop.sh
Phase 2 — Conditional Logic and Advanced Fields

Goal: The form adapts dynamically; all remaining field types available.

  • Conditional logic engine (useConditionalLogic) with all six action types and AND/OR condition groups
  • 12 advanced field components: Multi-select, Linear scale, NPS, CSAT, Star rating, Ranking, Matrix, File upload, Signature, Hidden, Calculated, CAPTCHA
  • Answer piping: @fieldName token interpolation in question text and Thank You page
  • Custom Thank You page and redirect on completion
  • S3-compatible file storage backend; webhook dispatch with 5-attempt retry queue
Phase 3 — Theming, Embed Modes, and Notifications

Goal: Forms fully branded; all three embed modes work; rich notifications fire reliably.

  • Full theming: CSS custom properties (colour, font, logo, cover image), custom CSS injection per form
  • Popup embed mode: modal overlay + AJJForms.open() / close() JS API + declarative trigger
  • Full-page embed mode; dynamic height via postMessage
  • Host-page URL query parameter auto-forwarding to hidden fields; prefill attribute support
  • Respondent email notification; dynamic To: routing via calculated field
  • Optional reCAPTCHA / hCaptcha per form (server-side token verification)
Phase 4 — Security Hardening, Testing, and Documentation

Goal: Production-ready, secure, fully tested, and documented.

  • Redis-backed rate limiting; CSRF double-submit cookie; partial submissions; duplicate prevention; password gate
  • Unit tests (Vitest): all composables, all field components — minimum 80% coverage
  • Integration tests (Supertest): all API endpoints
  • End-to-end tests (Playwright): inline, popup, multi-step, conditional logic, file upload
  • Full documentation set (Architecture, Quickstart, EmbeddingGuide, SchemaReference)
  • Docker Compose production deployment package

7. Embedding Interface Specification

Step 1 — Load the Script Once

<!-- Add once to <head> or before </body> -->
<script src="https://forms.ajj.com/embed.js" defer></script>

Step 2 — Choose a Render Mode

Inline Embed

<ajj-form
  form-id="abc123"
  mode="inline"
  dynamic-height="true"
  hide-title="false"
  align="center"
  transparent-bg="false"
></ajj-form>

Popup — Declarative Trigger (No JavaScript Required)

<button data-ajj-form="abc123" data-ajj-mode="popup">
  Contact Us
</button>

Popup — JavaScript API

window.AJJForms.open('abc123');
window.AJJForms.close('abc123');

Full-Page Embed

<ajj-form
  form-id="abc123"
  mode="fullpage"
  transparent-bg="true"
></ajj-form>

Pre-fill via URL Parameters (Automatic — No Config Required)

https://example.com/contact?email=alice@example.com&ref=newsletter
<!-- Fields "email" and "ref" auto-populated from URL params -->

Pre-fill via Attribute

<ajj-form
  form-id="abc123"
  prefill='{"email": "alice@example.com", "source": "homepage"}'
></ajj-form>

JavaScript Events API

window.AJJForms.on('submit', 'abc123', function(payload) {
  gtag('event', 'form_submit', { form_id: payload.formId });
});

window.AJJForms.on('page-change', 'abc123', function(data) {
  console.log('Page ' + data.pageIndex + ' of ' + data.totalPages);
});
